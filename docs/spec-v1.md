# Floatnote 要件・設計 v1

作成日: 2026-11-01。実装前の基準。変更時は別版を作成し、この版を保持する。

## 目的と範囲

Windows の付箋のように、複数の小さな独立ウィンドウへすぐ書けて、それぞれが一定周期で手前へ戻るデスクトップアプリを作る。公開 GitHub リポジトリへソースと再現可能なビルド手順を公開する。アプリ名は Floatnote、リポジトリ候補は menma22/floatnote。

クラウド、アカウント、同期、タスク管理、常設ホーム画面は設けない。メモは PC 内だけに保存し、アプリからネットワーク通信しない。

## 意図する振る舞い

1. 初回起動時は空の付箋を 1 枚だけ開く。次回以降は開いていた付箋と位置・大きさを復元する。すべて閉じていた場合は一覧を開く。
2. 各付箋は独立したリサイズ可能な Windows ウィンドウ。ヘッダーの `＋` で新しい付箋を作る。内容と周期は付箋ごとに独立する。
3. ヘッダー 1 段に、新規作成、一覧、周期スライダーと値、最小化、最大化／元に戻す、閉じるをまとめる。本文を主役にし、下部ツールバーは置かない。
4. 周期の初期値は 30 分。スライダーは 5〜120 分、5 分刻みで 15 分・30 分を簡単に選べる。周期変更後はその時点から計り直す。値は常に `30分` のように表示する。
5. 周期を迎えた開いている付箋は他の通常ウィンドウの手前へ戻る。最小化された付箋も戻す。常時最前面には固定しない。暫定方針は、編集中の別アプリの入力フォーカスを奪わず、短時間だけ最前面にして解除する。本人へ確認中だが、この方針で実装を進める。
6. スリープ中に積み残した回数分を連打しない。復帰時には期限を過ぎた付箋を 1 回だけ表示し、次回を現在から再計算する。OS がロック中・セキュアデスクトップ・排他フルスクリーン中の表示は保証できない。
7. `×` はメモを削除せず閉じる。この付箋の周期も停止する。一覧から開くと周期を再開する。最小化は周期を停止しない。
8. 全付箋を閉じても通知領域で動作する。通知領域メニューから新規作成、付箋一覧、終了へアクセスできる。終了はすべてを保存してプロセスを止める。OS ログイン時の自動起動は今回追加しない。
9. `**太字**`、`- 箇条書き`、`1. 番号付きリスト` を入力できる。Enter で確定した行の記法を表示へ変換し、続けて編集できる。日本語 IME の変換確定 Enter では改行・変換しない。太字の Ctrl+B、取り消し Ctrl+Z、貼り付けも利用できる。対応外 Markdown は本文として保持する。
10. ヘッダーの一覧ボタンで別の小さな一覧ウィンドウを開く。本文から作った見出し・抜粋・周期・開閉状態を表示し、付箋をクリックすると再表示する。新規作成と検索を提供する。メモの永久削除は実装しない。
11. 本文、周期、開閉状態、ウィンドウ位置とサイズを Electron の userData 配下へ保存する。保存失敗は隠さず表示し、既存の破損ファイルは上書きせず停止する。通常の再起動・終了直前の入力も保持する。

## 設計

- Electron の main プロセスがウィンドウ、タイマー、保存、通知領域を管理する。vanilla JavaScript + Vite + Tiptap が本文とヘッダーを描画する。PC に開発環境がなくても動く Windows 配布物を用意する。
- UI は淡い黄色の付箋、読みやすい濃い本文、コンパクトなヘッダー。初期サイズ 420×380、最小サイズ 400×240。ドラッグ領域をヘッダーに残し、ボタンとスライダーはドラッグしない領域にする。
- 保存モデルは `version: 1, notes: [...]`。note は `id, content`（Tiptap JSON）, `text`（一覧用プレーンテキスト）, `intervalMinutes, isOpen, bounds, createdAt, updatedAt`。新規付箋の内容は空の paragraph。
- renderer は Node.js やファイルへの直接アクセスを持たず、sandbox/contextIsolation を有効にした preload の限定 API を使う。外部遷移、新規ウィンドウ、リモートリソースは禁止する。IPC はウィンドウの役割と入力を確認する。
- 通常実行と検証用データを分離する。E2E は `FLOATNOTE_TEST_USER_DATA` で別フォルダを指定し、`FLOATNOTE_TEST_MODE=1` では二重起動制限とトレイを避ける。テスト環境以外で短縮周期や検証 API を公開しない。

### preload API 契約

全メソッドは `window.floatnote` 上。購読関数は解除関数を返す。

| メソッド | 入力と返り値 |
| --- | --- |
| `getInitialState()` | Promise `<{kind:'note',note} \| {kind:'list',notes}>` |
| `createNote()` | Promise、作成された note を返す |
| `openList()` | Promise void |
| `openNote(id)` | Promise void、一覧からのみ |
| `updateNote({content,text})` | Promise void、送信元の付箋のみ更新。1回の本文変更ごとに送る |
| `setInterval(minutes)` | Promise void、送信元の周期更新 |
| `minimize()` | Promise void |
| `toggleMaximize()` | Promise boolean、最大化状態を返す |
| `closeWindow()` | Promise void |
| `onNotesChanged(callback)` | callback(notes)、一覧用 |
| `onResurface(callback)` | callback()、表示演出用 |
| `onError(callback)` | callback(message)、保存などのエラー |

renderer は本文変更を main へ即時送信する。main 側が書込回数をまとめ、閉じる・終了で必ず確定する。周期値の更新・一覧の再描画で入力内容を再設定しない。

## 成功条件・検証予定

| ID | 確認するユーザー動作・結果 | 確認方法 |
| --- | --- | --- |
| A1 | 初回は付箋 1 枚だけ、＋で独立した 2 枚目が開く | Electron E2E・実物確認 |
| A2 | 周期の初期値 30 分、15 分へスライドして保存・再起動で保持 | E2E・保存検査 |
| A3 | 実際のスケジューラから小窓が手前へ戻り、後で最前面固定が解除される | 短い実時間を使った同じスケジューラの E2E、実機確認 |
| A4 | 付箋ごとの期限、周期変更、閉じる、復帰で二重・連続表示しない | 決定的な単体テスト |
| A5 | 太字・両リストを Enter で表示へ変換、日本語を保持 | エディター E2E・実物確認 |
| A6 | 閉じると消え一覧から復元でき、保存した本文を保持 | E2E |
| A7 | 最小化・最大化・リサイズ・移動が使え、再起動で本文と位置を復元 | E2E・実物確認 |
| A8 | 保存失敗・不正 IPC・破損ファイルでデータを黙って失わない | 単体テスト・E2E |
| A9 | Windows 配布物が生成され、開発環境なしで起動できる構成 | Windows ビルド・配布物起動 |
| A10 | 公開 GitHub リポジトリが存在し、公開したコミットがローカルの検証対象と一致 | GitHub と remote ref の読取 |

実装中に追加した判断は次版へ残す。実装後に条件ごとのコード・結果・未検証事項を別の検証記録へ照合する。
