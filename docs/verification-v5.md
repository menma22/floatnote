# Floatnote 実装照合・検証 v5

2026-11-02。前版 [v4](verification-v4.md)、最終設計 [v9](spec-v9.md)。

## 最終実装

新規付箋と一覧は `loadFile()` 呼び出しの直後に `show()` する。初回描画や読み込み完了のイベントを待たない。保存済み付箋の起動時表示には `showInactive()` を使い、周期再表示のコードは変更していない。

中間方式の `did-finish-load` 待ちでも、デバッガーのない実アプリで表示が遅れるケースを観測したため、この待機も除いた。v4の速度を最終実装の結果として引用しない。

## 実物の照合

このPCのFloatnote 0.1.2を最終インストーラーで更新し、インストーラー終了コード0と、配置された `resources/app.asar` が最終ビルドとSHA256で一致することを確認した。既存メモ7枚は更新前のバックアップとバイト単位で一致した。公開Releaseはこの作業では更新していない。

インストール先の実行ファイルを一時データで検査した。メインプロセスのウィンドウ `show` イベントで測った操作から表示までの時間は、＋100ms／一覧109msだった。ネイティブ可視状態、本文側UIと一覧項目も確認した。

自動操作・デバッガー接続を含めた全体の完了待ちは、冷間の新規付箋で2307ms、一覧260msだった。これには測定器の接続待ちも含まれるため、実ウィンドウの表示時間と区別して両方を記録する。本文まで全環境で1秒以内に準備できるとは保証しない。

速度テストはネイティブ `show` までを1秒未満で検査し、DOM側も別途確認する。単に計測終了までの時間を使うとデバッガー接続時間までアプリの表示遅延として測ってしまうため、イベントの時刻で表示そのものを計測する。

整形・ESLintは最終状態で成功。単体35件とその他のWindows操作の確認はv4を参照する。周期再表示の入力保持に旧版と同じ検証失敗が残る点、およびMacの今回の追加検証が未実施である点も引き継ぐ。
