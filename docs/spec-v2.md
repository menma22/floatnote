# Floatnote 要件・設計 v2

作成日: 2026-11-01。前版: [v1](spec-v1.md)。v1 の全文を引き継ぎ、以下の確定事項・追加要件を適用する。v1 の本文は保存する。

## 本人確認による確定

周期到達時は付箋を手前に戻し、今操作しているアプリの文字入力フォーカスを奪わない。v1 の「暫定」「確認中」はこの版で確定となる。最小化された付箋にも同じ条件を適用する。

## 色と最小限の UI

本人の追加依頼: 「付箋のカラーは選べつつ」「デフォルトの色は…見えにくくないもの」「モダンかつ極限までシンプルなUI」。

- 付箋ごとに、クリーム、セージ、ブルー、ローズ、ラベンダー、グレーの 6 色を選べる。既定は淡いクリーム。すべて濃い本文との可読性を保つ。
- 色選択はヘッダーの小さな色ボタンからパレットを開く。常設の大きな設定パネルを設けない。キーボードと読み上げ名で操作でき、選択状態を色だけに依存させない。
- アイコンは細い線の SVG に統一する。装飾的な見出し、キャッチコピー、カード、下部ツールバーは追加しない。400px 幅でもすべてのヘッダー操作を 1 段に収める。
- 本文の入力を主役とし、必要な説明は空の付箋やツールチップでのみ示す。

## 保存・API の拡張

- note の `color` は `cream | sage | blue | rose | lavender | gray`。新規は `cream`。保存して再起動時に復元する。旧データで未指定の場合も `cream` を補う。
- `window.floatnote.setColor(color)` は Promise void。送信元の付箋だけを変更する。main が enum を検証する。
- 一覧の表示更新と、本文を編集中の色変更は、本文・キャレット位置・取り消し履歴を消さない。

## 成功条件の追加

| ID  | 条件                                                        | 確認方法               |
| --- | ----------------------------------------------------------- | ---------------------- |
| A11 | 色を選択するとその付箋だけ変わり、再起動後も保持される      | E2E・実物確認          |
| A12 | 400px 幅でヘッダーが 1 段に収まり、本文の表示面積を確保する | DOM 寸法計測・画面確認 |

実装後は A1〜A12 を実コードと確認結果へ照合する。以後の実装判断は検証記録で根拠とともに追記し、要件を変更する場合は v3 を新規作成する。
